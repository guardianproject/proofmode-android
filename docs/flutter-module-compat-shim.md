# Flutter Module Compatibility Shim (AGP 9)

## Why this is needed

Proofmode embeds a local Flutter module at `flutter-location-protocol/` for the Location Protocol bridge.

In this branch/toolchain, Flutter module generation currently emits `.android/Flutter/build.gradle` that applies `dev.flutter.flutter-gradle-plugin`. Under AGP 9.x this can fail during Gradle configuration with a `NullPointerException`, which blocks host app compilation.

Because `.android/Flutter/build.gradle` is generated by Flutter tooling, this file can be overwritten after commands like:

- `flutter pub get`
- `flutter build ...`
- any command that regenerates `.android/`

## Required action after regeneration

Re-apply the Proofmode shim immediately after Flutter regeneration.

### Where to run Flutter regeneration

Run Flutter module regeneration commands from the Flutter module directory:

- `flutter-location-protocol/`

Examples:

- `cd flutter-location-protocol && flutter pub get`
- `cd flutter-location-protocol && flutter build aar`

Running host Android Gradle builds from the repo root does not itself regenerate this file. The file is typically rewritten when Flutter tooling regenerates `.android/`.

### Source of truth

Use the tracked shim template:

- `flutter-location-protocol/flutter-android-build-shim.gradle`

### Apply command (Linux/macOS)

```bash
cp flutter-location-protocol/flutter-android-build-shim.gradle \
  flutter-location-protocol/.android/Flutter/build.gradle
```

### Apply command (Windows PowerShell)

```powershell
Copy-Item "flutter-location-protocol/flutter-android-build-shim.gradle" "flutter-location-protocol/.android/Flutter/build.gradle" -Force
```

### Verify compile

```bash
./gradlew :plugin-location-protocol:compileDebugKotlin
./gradlew :app:compileDefaultDebugKotlin
```

Windows PowerShell equivalent:

```powershell
.\gradlew.bat :plugin-location-protocol:compileDebugKotlin
.\gradlew.bat :app:compileDefaultDebugKotlin
```

## What the shim does

- Avoids applying `dev.flutter.flutter-gradle-plugin` in generated module.
- Declares a minimal `com.android.library` setup for the generated Flutter subproject.
- Adds Flutter engine jar as dependency:
  - `$flutterSdkPath/bin/cache/artifacts/engine/android-arm64/flutter.jar`
- Adds required AndroidX annotations dependency used by generated registrant stubs.

## Important note

This is an AGP/Flutter compatibility workaround for host-module compilation. Keep this document updated when Flutter/AGP versions are upgraded, and remove the shim once upstream compatibility is confirmed.
